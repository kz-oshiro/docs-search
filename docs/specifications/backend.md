# docs-search 再構築版: バックエンド仕様

現行の詳細仕様。要求ID・上限・自動テストとの対応は[Rust要求仕様](rust-requirements.md)、実施結果は[公開・検証記録](../releases/README.md)を参照。

検索バックエンドはフォルダーの列挙、文書からの文字列抽出、照合、結果と進捗の通知を担当する。GUI や OS の画面部品には依存しない。入出力の意味は [境界契約](boundary.md) に定義する。

## 列挙と検索規則

1. 指定された検索フォルダーを再帰的に列挙し、下表から選択された拡張子のファイルだけを対象とする。対象外フォルダーとその配下は列挙しない。対象外指定は検索フォルダーの指定より優先し、検索フォルダー同士が重なっても同じパスのファイルを二重計上しない。拡張子は大文字・小文字を区別しない。未選択の形式と対象外フォルダー内のファイルは発見・処理・結果・エラーの件数に含めない。隠し属性や先頭のドットだけでは除外しない。`~$` で始まる Office 一時ファイルとシンボリックリンクは除外する。
2. 通常検索の検索語は前後の空白を取り除き、空なら入力エラーとする。通常欄は正規表現や複数語演算ではない1語句として扱う。高度な検索は構造化した条件群を別に指定する。
3. 原文を表示用に保持し、NFC と Unicode case folding による基本形、NFKC と case folding による幅吸収形、かな種別と識別子区切りを吸収した検索形を別に作る。アクセント除去、語幹変化、同義語展開は行わない。大文字境界は case folding より先に検出する。数字だけの検索語では区切り記号を除去しない。
4. ファイル名は拡張子を含めて照合する。内容の一致は下表の「検索単位」ごとに判定し、同じ単位に検索語が複数回出ても結果は 1 件とする。別の単位、ファイル名と内容の一致は別件とする。
5. 検索対象の値は保存済みデータに限る。文書を編集・再計算・実行しない。外部参照の取得もしない。

検索中にファイルが変化した場合は、そのファイルの読み取り時点で得られた内容を扱う。一貫したスナップショットは保証しない。途中で読めなくなったファイルは個別エラーにする。

## 形式ごとの抽出範囲

| 形式 | 検索単位と内容 | 場所情報 | 初期版の対象外 |
| --- | --- | --- | --- |
| `.xlsx` / `.xlsm` | セルの保存値・保存済み数式結果、図形・テキストボックス。`includeFormulas` で保存された数式文字列、`includeNotes` で従来・スレッドコメントを追加。書式ランは連結する。 | シート名と番地、図形名・位置、コメントID | 未保存の計算結果、表示書式後の値、グラフ、SmartArt、マクロ |
| `.pptx` | 通常のテキスト図形・表セル。`includeNotes` でノート本文を追加。書式ランは連結する。 | スライド番号と図形名、表の行・列、ノート図形ID・段落 | マスター、埋め込み文書、グラフ、SmartArt、画像中の文字 |
| `.docx` | 本文と表内段落。`includeNotes` でヘッダー・フッター・コメント内の段落と表を追加。 | 部品・種類・段落、表の階層・行・列、コメントID | 脚注、文末脚注、変更履歴の削除部分、埋め込み文書、画像中の文字 |
| 上表の Office 以外の拡張子 | UTF-8、UTF-8 BOM、Shift_JIS（Windows-31J 相当）で読んだ各行の文字。コード・マークアップ・CSV・JSON・ノートブックなどの構文を解析せず、保存された文字列をそのまま照合する。 | 1 始まりの行番号 | 他の文字コード、バイナリ、改行をまたぐ一致、実行・レンダリング後の文字 |

Excel の数値は保存された文字列を使い、日付等の表示書式を適用しない。論理値は `TRUE` / `FALSE`。保存済みの数式結果は従来どおりセル値として扱い、`includeFormulas` では `=` を付けた保存式を別の `formula` 単位として返す。共有式は保存された基点だけを検索し、`sharedIndex` / `formulaRange` を保持する。本文のない従属式は再構成しない。図形はシート・スライドと位置または通し番号で区別する。

`includeNotes` / `includeFormulas` の初期値・省略値は偽。追加部品はリレーションから辿る。ノートの `dt` / `ftr` / `hdr` / `sldNum` / `sldImg` プレースホルダーは除く。Wordの同じ共有部品は1回だけ抽出する。Excelコメント本文を取得できた番地では、対応するVMLの `ObjectType=Note` を除く。オフ時は既存のVML図形検索を維持し、コメント部品の取得失敗時も取得済みVMLを残す。スレッドの返信は親から番地を継承できる範囲（最大16段）で解決し、取得できない番地を推測しない。

注記部品の欠落・XML破損・不正UTF-8・部品単位の上限・外部参照は、部品名付きの `read` Issue とする。本文は保持し、同じ部品の同じ障害は重複通知しない。不完全な抽出を索引へ保存せず、ファイル範囲の条件は成立させない。単位・Excel行の条件と通常/一括検索は取得済みUnitを評価する。主文書・本文が読めない、ZIP全体が不正、総展開量128MiB・部品数4096の上限の場合はファイルエラー。各部品は32MiBまで。

非表示シート・非表示スライドも対象とする。Word の表内段落は本文の段落として重複計上しない。入れ子の表は外側からの表・行・列の経路で場所を示す。PowerPoint の表セルも図形全体の文字として重複計上しない。テキスト形式はファイルごとに UTF-8 BOM を優先し、BOM がなければ UTF-8、読めない場合は Shift_JIS として解読する。デコードできないデータは置換文字にして検索を続けず、そのファイルの読み取りエラーとして報告する。

## 処理単位と失敗

- ファイル単位で抽出処理を分離する。1 ファイルの破損、暗号化、権限不足、形式不正はそのファイルのエラーとし、残りのファイルを継続する。
- 列挙中のアクセス拒否などは、取得できたパスと理由を列挙エラーとして報告し、探索できる別の場所を続ける。
- 全体失敗は、検索を開始・継続できないバックエンド自身の障害に限る。個別エラーがあっても処理を終えたなら「完了（一部エラーあり）」に相当する集計を返す。
- 不正な入力は検索開始前に検出する。検索途中の中断では、既に通知済みの結果・エラーを取り消さない。
- 追加の検索フォルダーと対象外フォルダーも、存在するディレクトリか検索開始前に検証する。重複・親子関係は正規化したパスで判定する。
- 検索のたびにフォルダーの現状を調べる。`useIndex` が真なら検索単位の原文と正規化形をアプリのユーザーデータ領域のローカル索引に保存し、更新日時とサイズが変わったファイルだけ再抽出する。偽なら索引を読み書きせず文書を毎回読み直す。索引を使えない場合も文書を読み直して検索を続ける。元文書への書き込みや外部送信はしない。
- 抽出結果は検索単位ID、Office部品、グループ、Excelセルの物理座標、内容区分と取得済みアンカーを保持する。Excelの同じシート・同じ物理行のセルは同じグループとし、図形や他形式をセル行に推測で合流させない。結合範囲、非表示行・列範囲はシート単位の疎なメタデータとして保持し、空セルを最大行・列まで展開しない。
- 索引の保存形式と抽出仕様版を管理し、既存形式の索引は元文書から再構築する。鮮度はファイルのサイズ・更新日時に加え、抽出仕様版・抽出範囲で判断する。読み取り前後にサイズ・更新日時が変わった場合は `changedDuringRead` を報告し、その抽出結果を索引へ確定しない。これは検出できる変更の範囲であり、検索全体の一貫したスナップショットは保証しない。

## あいまい検索と順位

`fuzzySearch` が偽なら、NFC と Unicode case folding で正規化した検索語の部分一致だけを使う。原文の語句一致は `exact` (100)、大小文字や NFC の差を吸収した語句一致は `caseFolded` (98)、その他の部分一致は `substring` (70) とする。幅差・区切り差・かな種別差・タイプミス候補は扱わない。以下の規則は `fuzzySearch` が真の場合に適用する。索引の指定とは独立している。

原文の語・識別子一致 100、NFC と case folding 98、NFKC の幅差 95、空白・区切り記号差 92、identifier 分割一致 90、かな種別差 88、トークン前方一致 80、部分一致 70、編集距離一致 50 とする。検索単位内で最も強い方式を採用し、同じ単位は1件だけ通知する。N-gram は索引から候補を絞る用途だけに使い、共有 N-gram だけでは結果にしない。

編集距離は英字だけの単一トークンで6～10文字は距離1、11文字以上は距離2までとし、先頭文字一致と距離÷検索語長 0.2 以下を条件にする。5文字以下、数字や英数字混在コード、日本語には適用しない。索引が有効なときは短い検索語について索引内の検索単位を走査し、文書を毎回再抽出しない。索引の破損・形式変更時は再構築する。索引の削除操作は GUI から実行できる。

## 高度な検索

`querySpec.mode=conditions` では、改行ごとに入力された `all`・`any`・`not` の各語句を独立して評価する。式は全 `all` AND いずれかの `any` AND NOT いずれの `not` で、空の正の群は条件を課さない。両方の正の群が空なら開始しない。各群の重複語句は NFC と case folding でまとめ、語句内の空白や AND / OR という文字はそのまま扱う。

`unit` は元の検索単位ごと、`excelRow` は Excel の同じシート・物理行のセルと検索範囲内の数式Unitをまとめて判定する。Excel 図形や他形式は `excelRow` でも独立した検索単位とする。`file` はファイル名と文書内の全検索単位を同じ範囲として判定する。除外語は同じ範囲の全単位に対し NFC と case folding の部分一致で評価し、あいまい検索の編集距離では除外しない。ファイルの読み取りに失敗したときは不完全な内容からファイル範囲の成立を作らず、独立したファイル名の結果と Issue だけを保持できる。

通常検索は従来の1単位1件を維持する。高度な検索は成立した1単位・1行・1ファイルにつき1件とし、成立した正の語句ごとに最良の検索単位を根拠として返す。`matchType` と `score` は先頭の根拠の単一語句の方式・点数であり、複数語の確率や総合点ではない。索引利用時は対象ファイルの保存済み検索単位を全件読み、同じ範囲の正・除外条件を評価する。候補セルだけで NOT を判定する省略はしない。索引なしでは元文書から抽出する。

## Excel 周辺セル

検索通知は一致箇所のみを運び、周辺セルは `searchId` と `resultId` を指定したときに取得する。受理済みの最新検索の結果識別子とファイルのサイズ・更新時刻を保持し、終了後も次の検索まで参照できる。取得前後にファイル情報を確認し、変更・移動・削除された結果へ現在のセル値を混ぜない。索引を有効にした検索では、対象ファイルの索引が有効なら保存済みセルとシートメタデータから指定範囲だけを読む。索引が無効または未使用なら元の Excel 文書を読み直す。

要求範囲は各辺5以下で、一致行を含むことを検査する。応答は値のあるセルだけを返し、空欄をシート全体へ展開しない。結合範囲が窓と交差するときは、左上起点が窓外でもその値を取得する。非表示の行・列は省略せず、表示用情報として返す。セル値は300文字、交差する結合範囲は25件を上限とする。失敗はその結果の周辺表示だけに返し、検索結果・検索集計へ追加しない。

## 安全性と拡張性

- 文書は読み取り専用で開き、マクロ・スクリプト・埋め込みオブジェクトを実行しない。外部 URL、外部ファイル参照、外部実体を解決しない。
- 圧縮文書の展開量や XML 等の解析に対して、過大な資源消費を防ぐ制限を設ける。制限に当たったファイルは理由を示す個別エラーにする。
- 形式ごとの抽出器は、共通の「検索単位の文字列と場所」を返す責務に限定する。列挙、照合、進捗集計、キャンセルは共通部分で扱う。新形式の追加で GUI と既存形式の検索規則を変更せずに済むこと。
- 性能のために並列化やバッチ処理を採用してよい。ただし結果件数、各結果の場所、終端通知の意味は変えない。結果の到着順には依存しない。

概念上の流れは「対象ファイルの列挙 → 形式別の検索単位抽出 → 共通の照合 → 結果・エラー・進捗の通知」である。これは処理責務の分割であり、クラス構成やプロセス構成を指定しない。

## コアでの順位と一括検索

ファイル順位は `ranking.rs` に集約する。語ごとの最良の一致品質のうち最も弱いもの、異なる正の語数、同じExcel行に揃う語数（2語以上）、本文の異なる根拠数、異なる根拠数の順で比較する。根拠の場所は部品とUnitで重複排除し、本文・全根拠数とも最大5。反復だけで無制限に順位を上げない。最後はNFC/case foldingしたパス、元パス、構造化した座標・表経路・段落順で固定する。各ヒットのscoreの意味は維持し、総合確率へ読み替えない。GUIはこの結果を受信する。

一括検索は256語までの検証済み語句を同じ文書のUnitへ照合する。識別子はASCII英字/アンダースコアで始まる英数字/アンダースコアの語とし、通常の文字列検索を選べば日本語等も利用できる。各語の件数とファイル数は実際の通知から集計し、0件の確定には全範囲の完了とIssueなしを必要とする。文字列の登場箇所だけを示し、更新・呼び出し等の依存関係を断定しない。現段階の索引経路はファイルのUnit全件を1回読んで各語へ照合する。候補の省略による検索漏れを避け、語数分の再抽出をしない。大規模データでの負荷は別途確認する。

## 既存イシュー対応の追加契約

Excelのセル文字列は共有文字列・インライン文字列の通常のt要素を順番に連結し、rPh/phoneticPr配下の非表示ふりがな情報を除く。通常・あいまい・条件・一括・抜粋・元一致範囲・周辺表はこの同じ文字列を使う。抽出仕様版4を保存し、次の索引有効化時に検索フォルダー外も含め古い版の記録を破棄し、対象ファイルは一致候補を読む前に再抽出する。ブック内のsheetIndexと疎な保存書式も索引へ保持する。

ファイル順位は従来の一致品質・語数等を維持する。ファイル内の箇所は品質によらずdocumentOrderで位置順にし、Excelはブック内シート順・行・列の数値を使う。テキストは行、PPTはスライドと抽出位置、WordはXML内の段落/表の抽出位置を使う。未知の位置は取得できる部品内の抽出順へ戻し、位置を捏造しない。

検索処理は読み取り専用のままである。明示したテキスト編集の対象位置と保存処理はedit.rsで分離する。検索時に編集リビジョンを生成し、取得時の全元バイト・元行と一致範囲を検査する。保存時は取得した全元バイトと比較し、対象範囲以外を元のバイトで保持する。検索セッション以外の任意パスからの編集を受け付けない。対応範囲と制約は[GUI仕様](gui.md)、確認方法は[イシュー確認方針](../test-plans/issues-test-plan.md)を参照。
