# proptest の確認方針

現行の実行入口は[開発手順](../development.md)、機能基準は[Rust要求仕様](../specifications/rust-requirements.md)、公開版の検証結果は[GitHub Releases](https://github.com/kz-oshiro/docs-search/releases)を参照する。試験設計は同じ文書を更新し、改訂履歴をGitで管理する。

作成日: 2026-10-03。対象は [Rust要求仕様](../specifications/rust-requirements.md) の検索コア。固定の具体例・Office fixture・CLI受け入れを保持し、入力の組合せを生成して検証する性質テストを追加する。GUI・Windows配布ビルド・公開は今回対象外。

## 設計と依存関係

`core/Cargo.toml` のdev-dependenciesへ `proptest 1.11` を追加し、lockは1.11.0を記録する。default-featuresを無効にしてstd/handle-panicsだけを使う。通常のアプリ/CLI依存へ含めず、テスト失敗時のpanicも縮小の対象にする。ライブラリの最低Rust版は1.85で、プロジェクトの既存動作条件Rust 1.90以降の範囲に収まる。

実装は [property_tests.rs](../../core/src/property_tests.rs) の15性質と [report.rs](../../core/src/report.rs) の2性質。単に例外が起きないことを確認するのではなく、正規化した文字列の部分一致モデル、範囲ごとの論理値モデル、語×ファイルの件数モデルと照合する。正常一致を含む入力も構成し、ランダムな別々の文字列による「ほぼ不一致」だけの検証にならないようにする。

## 項目・手順・期待結果

| 要求 | 生成する入力/手順 | 期待結果 |
| --- | --- | --- |
| R3-06 | 任意Unicode＋結合文字・ß・İ・Σ/ς・かな・全角・絵文字を多めに生成し、NFD化と再正規化 | 正準等価文字列で結果が同じ、正規化を再適用して変わらない |
| R3-06 | 独立した検索語/本文、および語を含む本文を生成。通常検索とNFC/case-foldの部分一致モデルを比較 | 一致の有無が同じ。元Unicode範囲が有効で、その強調文字列も語を含む |
| R3-07 | 同じ生成語/本文を通常とあいまいへ渡す | 通常の一致を失わずstandardを保持。あいまいの範囲も原文内 |
| R3-07 | あいまいの最終評価と直接経路の候補判定を比較 | 実際に一致するUnitを候補判定で落とさない。余分な候補は許容 |
| R3-08 | 生成文書を一時ファイル＋メモリ内SQLiteへ索引保存。通常/あいまいを直接評価と比較 | 候補の最終評価結果のUnit ID集合が直接評価と完全一致。プロセスのLOCALAPPDATAを変更しない |
| R3-06 | 長短のUnicode前後文と1〜200文字の選択範囲を生成して抜粋 | 選択範囲を削らず、preview内へ正しく移す。240文字を超えた場合だけ省略フラグ |
| R3-10 | 0〜300行のUnicode検索語を生成し、空白/正規化重複を除く順序モデルと比較 | 最初の表記と順序、連続term IDを保持。0語/256語超は拒否 |
| R3-10 | 有効ASCII識別子とUnicode英数字/_/区切り/絵文字の隣接文字を組み合わせる | 両側の識別子境界が成立するときだけ一致。あいまいオン/オフでも同じ範囲・方式・点数 |
| R3-09 | シート・物理行・alpha/beta/除外の有無を生成し、unit/行/fileごとに論理値を集約 | AND/NOTの成立数がモデルと同じ。行の根拠は同じシート/行、通常成立ならstandard |
| R3-13 | 品質/語数/行/根拠数/パスの3つの順位入力を生成 | 比較の反対称性・反射性・推移性を満たす |
| R3-13 | 語・場所・点数・本文区分のヒットを生成し、反転と重複追加 | 到着順で順位根拠/位置順が変わらず、同じ根拠の重複で評価を増やさない。根拠数は5上限 |
| R3-04 | Unicodeの複数行、BOMの有無、LF/CRLFを生成して抽出 | 行内容と1始まりの行番号を保持し、Unit IDは一意。先頭BOMを内容に含めない |
| R3-17 | Unicode前後文・置換文字、BOM、改行と保存/キャンセル/外部更新を組み合わせる | 保存は対象以外のバイトを保持、キャンセルは不変、同じバイト数の外部変更も拒否して上書きしない |
| R3-11/R3-12 | ファイル/行の一致有無、破損ファイル、通知済み件数での中断を生成して公開API検索 | 独立モデルと結果数/中断理由が一致。開始/終端1回、連番、件数一致、順位は過去に通知したIDだけ |
| R3-10 | ファイル/行ごとに2識別子の有無・反復を生成して公開APIの一括検索 | 語別の箇所数/重複なしファイル数がモデルと一致。0件状態が正しく、語数分の再抽出をしない |
| R3-18 | 任意Unicode/制御文字の抜粋をJSON保存→読み戻し | 検索記録と抜粋が欠落/変形しない |
| R3-18 | 改行/タブ/引用/逆斜線/数式先頭を含む抜粋をTSV出力 | 行・列が増えず、制御文字をエスケープ。数式先頭を安全な文字列にする |

## 実行・失敗の再現

既存の `cargo xtask test` の `cargo test --locked` で性質テストも走る。既定は各256成功ケース（17性質で4,352ケース）で、保存済み失敗seedの再実行はこの件数と別に行う。`PROPTEST_CASES` で増減、`PROPTEST_RNG_SEED` で固定seedを指定できる。手順と設定の意味は [公式Config](https://docs.rs/proptest/1.11.0/proptest/test_runner/struct.Config.html) を参照。

```powershell
# 既定件数。固定ケース・CLI・JS構文確認も含む
cargo xtask test

# 17性質を指定seed/件数だけで実行する例
$env:PROPTEST_CASES = '1024'
$env:PROPTEST_RNG_SEED = '3000002'
cargo test --locked --manifest-path .\core\Cargo.toml --lib r3_
# 設定を残したくない場合は、実行前の環境値へ戻す
```

失敗するとproptestが入力を縮小し、`core/proptest-regressions/` にseedと最小入力コメントを保存する。保存seedは次回の生成より先に再実行する。[公式の失敗保存仕様](https://proptest-rs.github.io/proptest/proptest/failure-persistence.html)に従い、このディレクトリをGit除外しない。新しく生成したseedは差分として確認し、最小入力を意味の分かる固定回帰テストにも追加する。戦略を変更するとseedから生成される値が変わり得るため、固定回帰を併用する。

## 検出した回帰と修正方針

初回に本文 `a_` / 検索語 `a!` で、あいまい最終評価がidentifier一致を返す一方、`could_match` が落とす不整合を検出した。固定回帰と保存seedを追加し、最終評価の意味を変えず候補判定へ単一token/前方一致を含める。索引もraw検索語のN-gramに含まれないtoken一致を候補へ加え、区切りだけの語が保存gramにないため落ちる問題を防ぐ。

[索引CLI](../../core/tests/cli_index.rs)へ `a!` / `alpha!` / `__` を追加し、直接/索引初回/再利用の実際の結果が同じであることを確認する。通常検索や固定27ケースの期待値は変更しない。実施結果とログは[開発手順](../development.md#記録の自動生成と公開)に従って同じ実行の `outputs/runs/` に保存し、公開時はReleaseに検証記録を添付する。

性質テストは定めた生成範囲・件数での検証であり、全Unicode/全ファイル形式の証明ではない。Excel/Officeの互換性は既存fixture、OS権限の網羅・性能・GUIは別の確認範囲とする。
