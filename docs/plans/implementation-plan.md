## 1. 対象と方針

今回実装する機能は、前回提案の **1・2・3・4・6・7**。番号5の新旧設計書比較は対象外とする。

| 元の番号 | 機能 | 実現する利用者の行動 |
| --- | --- | --- |
| 1 | Excelの行・周辺セル表示 | ヒットした項目の型、桁数、必須区分、説明をアプリ内で確認する |
| 2 | AND / OR / 除外検索 | 複数条件を、同じセル・同じ行・同じファイルの範囲で判定する |
| 3 | 結果の一括コピー・CSV / TSV出力 | 検索結果を調査票に貼り、検索条件・エラーとともに記録する |
| 4 | 複数IDの一括検索・登場箇所一覧 | 複数の画面ID・テーブル名・項目名について、登場する文書を一度に調べる |
| 6 | Officeの検索範囲拡張 | Excelコメント・数式文字列、PowerPointノート、Wordヘッダー等を検索する |
| 7 | 検索順位の改善 | 複数条件への一致、同じ行への集中、本文の根拠を使って結果を並べる |

### 引き継ぐ条件

- 利用者がフォルダーを指定すれば使える。事前の辞書登録、学習データ、手動タグ、文書テンプレート設定は要求しない。
- 検索・抽出・順位付けは端末内で行う。外部サービス、LLM、外部Embedding、外部検索を導入しない。
- 元文書は読み取り専用。数式、マクロ、埋め込みコードを実行せず、外部リンクを取得しない。
- `useIndex` と `fuzzySearch` は独立し、未指定・画面の初期状態ではともにオフ。
- 現行の通常検索欄は、空白・AND・OR・記号を含めて「入力した1語句」として扱う。高度な検索は明示的に選ぶ。
- 索引を無効にした検索・周辺表示では、保存済み索引を読み書きしない。検索中に抽出したデータの一時的なメモリ利用は可能とする。
- 既存の複数フォルダー、対象外フォルダー、拡張子選択、重複排除、個別エラー、中断、通知順序の契約を維持する。
- 新機能の対象はTauri版。旧PowerShell版への同時追加は行わない。

## 4. P0: 共通基盤と境界契約

### 4.1 検索単位と行の表現

`Unit` を共通の抽出結果として維持し、以下を追加する。内部では構造化した型を使い、境界では現在のJSON形式との互換性を保つ。

| 項目 | 用途・規則 |
| --- | --- |
| `unitKey` | 同じ抽出スナップショット内で検索単位を識別する。部品、種別、場所、必要なら通し番号から生成する |
| `partKey` | Excelシート、Wordのヘッダー等のOffice部品を区別する |
| `groupKey` | Excelセルならシート内の物理行。その他はまず既存の検索単位ごとに付ける |
| `row` / `column` | Excelセルの1始まり座標。セル番地から求め、XMLの列挙順に依存しない |
| `contentClass` | 本文、注記、数式文字列を区別する。表示・絞り込み・順位付けに利用する |
| `anchor` | コメントなどの参照先セル・段落。取得できる場合だけ保持する |

`unitKey` は文書編集をまたぐ恒久IDではない。位置や値が変われば別のスナップショットとして扱う。コメントID・部品名など実ファイルから得られる値を使い、場所が不明なものを推測で補わない。

Excelはセル番地で疎に保持し、ワークシートの最大行・最大列まで空セルの配列を作らない。結合範囲は表示用に保持し、左上の値を他の行へ複製して検索ヒットを増やさない。

### 4.2 要求モデル

現行の `query` に加えて、任意の `querySpec` を導入する。

| モード | 内容 |
| --- | --- |
| 通常 | `querySpec` なし。現在の `query` の処理・結果単位を維持 |
| 複数条件 | 必須語群、任意語群、除外語群、判定範囲を構造化して指定 |
| 一括 | 検索語の配列と照合方法を指定。語ごとにIDを付ける |

`querySpec` がある場合、従来の `query` は空または未指定とする。両方を指定した曖昧な要求は項目別入力エラーにする。通常・複数条件・一括を一つの実行内で混在させない。

新しい入力欄は検索条件であり、導入時の設定ファイル・辞書は要求しない。単一語句の照合器を `fuzzy.rs`、条件の組み合わせを新しい `query.rs` に分離する。

### 4.3 結果と件数

- 通常検索は、現在と同じ1検索単位につき1ヒット。
- 行範囲の複数条件検索は、条件を満たす1行につき1ヒット。新しい `sourceKind=excelRow` と、根拠セルの配列 `evidence` を返す。
- ファイル範囲の複数条件検索は、1ファイルにつき1ヒット。新しい `sourceKind=fileMatch` と根拠の場所を返す。
- 一括検索は、正規化後の検索語IDと検索単位の組み合わせにつき1ヒット。
- `resultCount` はどのモードでも通知した `Result` 数と一致させる。ファイル数・根拠セル数・検索語数は別の表示項目にする。
- `matchType` と0〜100の `score` は、一語句の一致方式という現在の意味を維持する。複数語の情報とファイル順位を別項目にする。

複数条件の各根拠には、`termId`、`unitKey`、場所、抜粋、一致範囲、一致方式を保持する。GUI・出力がどの語をどこで見つけたか説明できることを必須にする。

### 4.4 索引

- DB版と抽出仕様版を明示し、現在の `user_version=1` から必要な版へ更新する。DB版の具体値は変更順に決める。
- 検索単位に `unitKey`、`partKey`、`groupKey`、座標、内容区分を保持する。`sourceKind` の保存・復元も全追加種別に対応させる。
- 周辺表で使うシート情報・結合範囲・非表示行列も、同じファイルと抽出仕様版に紐付くメタデータとして保存する。索引から周辺を表示するときだけ結合情報が失われる構成にしない。
- ファイルのサイズ・更新日時に加え、抽出仕様版と注記/数式の抽出範囲を保存する。
- 同じ文書でも注記・数式の対象指定が変わったら再抽出する。初期実装は抽出範囲が完全一致する場合だけ再利用し、複雑な差分補完を避ける。
- 再構築は元文書から行う。移行できない索引は破棄して再構築できるようにする。
- 読み取り前後のサイズ・更新日時が変わったファイルは、得た内容を新しい索引として確定しない。`changedDuringRead` を報告する。
- 変更検出はサイズ・更新日時で分かる範囲を対象にする。検索全体の一貫したスナップショットは、現在と同じく保証しない。
- 索引の障害時は現在と同じく直接読み取りへ戻る。索引あり/なしで検索結果の意味が変わらないことを合格条件にする。

## 5. P1 / 機能3: 一括コピーと出力

### 利用者に見える動作

結果欄に「一括コピー」「保存」を追加し、対象を「全結果」「現在の絞り込み結果」から選べるようにする。初期選択は現在の絞り込み結果。操作名または件数で対象が分かるようにする。

| 出力 | 内容 |
| --- | --- |
| TSVコピー | Excelへ貼り付ける結果表。ヘッダーあり |
| CSV保存 | UTF-8 BOM付きの結果表 |
| TSV保存 | UTF-8の結果表 |
| 調査記録保存 | JSONに検索条件、実行状態、集計、結果、Issue一覧を保持。結果表と同じ実行を記録できる |

標準列は「ファイル名、絶対パス、形式、内容区分、場所、抜粋、一致理由」。P3以降は検索語と根拠、P6では検索語IDを追加する。表示上省略された文字は省略済みであることを記録する。抜粋を元文書全文として扱わない。

### 実装

- GUIが保持する結果から対象集合を選ぶ。現在のDOMに描画されていない結果も対象にする。
- 絞り込み後の出力には、結果の絞り込み条件・出力件数を調査記録に含める。
- 出力専用の `report.rs` に、文書形式に依存しないデータモデルとCSV/TSV/JSON変換を置く。
- 保存先の選択と書き込みは `src-tauri` の操作として実装する。検索バックエンドから元文書フォルダーへ自動出力しない。
- 保存は利用者の操作で行う。CSV/TSVと調査記録は別の保存操作とし、複数ファイルを自動生成する前提にしない。
- CSVは区切り・引用符・改行をエスケープする。TSVではタブ・改行・バックスラッシュを一貫して文字表現へ変換し、表の列を壊さない。
- 表計算向け出力で数式と解釈される先頭文字を無害化する。JSONには原文を保持する。
- 保存先ダイアログの取消しは失敗として表示しない。書き込み失敗では検索結果を保持する。
- まず終了後の出力に対応する。中断・一部エラーでも出力でき、調査記録に状態を明示する。検索中の出力は初版では無効にする。

### 受け入れ条件

1. 200ファイルを超える結果でも、全結果の出力に未描画の結果が含まれる。
2. 絞り込み後の件数と出力件数が一致する。
3. 日本語、引用符、タブ、改行、空文字、数式として扱われる文字列を含む結果が列崩れなく出力される。
4. 一部エラー・中断・該当なしの状態とIssueを調査記録から確認できる。
5. 保存の取消し・失敗後も、元の結果と元文書が変わらない。

## 6. P2 / 機能1: Excelの行・周辺表示

### 表示仕様

一致箇所に「周辺を表示」を追加し、押すとセル番地付きの小さな表を表示する。初期表示は一致セルの前後2行・2列の最大5×5セルとする。これは表示上限の初期案で、性能試験の保証値ではない。

- 同じ行の離れたセルも確認できるよう、行の列方向に表示範囲を送れる操作を用意する。
- 一致セルを強調し、複数条件検索では各根拠セルも強調する。
- 結合セルは結合範囲を表示し、値を持つ左上セルが分かるようにする。
- シート名と行・列番号を表示する。列見出し・項目名を自動推測して確定ラベルにしない。
- 保存値・保存済み数式結果という現在の抽出規則で表示する。Excelの表示書式や未保存の再計算結果の再現は今回の対象に含めない。
- 非表示行・列の情報を取得して表示するが、検索対象から自動除外しない。
- シート上の図形は、取得できたアンカー周辺の表示に対応する。アンカーがない場合は場所を作らず、周辺表示の対象外と説明する。

### データ取得と変更検出

新しい `getResultContext(searchId, resultId, range)` を定義する。検索イベントの `Result` に周辺の全セルを大量に付けず、利用者が展開したときだけ取得する。

- 最新の検索セッションに結果の識別情報とファイルのサイズ・更新日時を保持する。
- 検索終了後も周辺を取得できる。次の検索を受理した時点で古いセッションを破棄し、遅れて届く応答をGUIが採用しない。
- 索引ありでは有効な索引を利用し、索引なしではメモリ内の抽出結果または元文書の再読み取りを使う。
- 検索時からファイルが変わっていた場合、古いヒットに新しい周辺を混ぜず、再検索が必要な状態を返す。
- 範囲・セル数・文字数に上限を設ける。空の大きな範囲を密な配列として展開しない。
- 一時的な文書キャッシュはバイト数に基づく上限と退避規則を設け、最大値は負荷確認で調整する。
- 周辺取得エラーは検索結果そのものを消さず、その結果の表示欄で説明する。

### 受け入れ条件

1. B12のヒットからA12の項目名とC12〜D12の情報を確認できる。
2. シートの左上・最終行列、空セル、飛び飛びのセルでも範囲外参照が起きない。
3. 結合セルの表示によって検索件数が増えない。
4. 検索後の編集・移動・削除を検出し、古い検索結果との混在を防ぐ。
5. 索引あり/なしで同じ周辺値を表示する。

## 7. P3 / 機能2: 複数条件検索

### 入力仕様

通常の検索欄を維持し、「高度な検索」の欄で次を指定する。

| 欄 | 判定 |
| --- | --- |
| すべて含む | 各語句をすべて含む（AND） |
| いずれか含む | 1語句以上を含む（OR）。空ならこの条件を課さない |
| 含まない | どの除外語句も含まない（NOT） |
| 判定範囲 | 同じ検索箇所 / 同じ行（Excel） / 同じファイル |

各欄は改行で複数語句を受け付け、1行は空白を含めて1語句とする。前後空白と空行を取り除く。同じ判定群の重複語を正規化してまとめる。

式は **「すべて含む」AND「いずれか含む」AND NOT「含まない」**。必須語群が空ならそのAND条件を課さない。必須語群・任意語群の両方が空の除外だけの検索は拒否する。同じ語を必須語と除外語に入れた明白な矛盾は開始前に説明する。

この段階では通常検索欄に演算子の構文解析を導入しない。複雑な括弧式・正規表現は対象外とし、UIで意味が確認できる条件構築を先に完成させる。

### 判定範囲

| 範囲 | 意味 |
| --- | --- |
| 同じ検索箇所 | 既存のセル・図形・段落・表内段落・テキスト行などの1単位に条件を適用 |
| 同じ行（Excel） | 同じシートの同じ物理行にあるセルをまとめる。別セルの語もANDを成立させる |
| 同じファイル | 有効な抽出範囲の全文書単位に条件を適用。根拠の場所を返す |

高度な検索の初期範囲は「同じ行（Excel）」とし、Excel以外は同じ検索箇所として扱うことを画面に明記する。その他の文書で表の行を横断する高度化は後続拡張とし、今回のExcel対応と混同しない。

ファイル名は検索箇所/行範囲では独立した1単位として判定し、ファイル範囲では文書内容とともに条件判定の対象とする。ファイル名の語と別セルの語がANDを成立させるのはファイル範囲だけにする。

Excelの図形は行アンカーがあってもセルの行検索へ合流させない。数式・コメントは対象指定が有効で、参照先セルが分かる場合にその行へ結び付ける。参照先が不明なら独立した単位にする。

### 照合と索引

- 正の語句は既存の通常/あいまい検索の指定を使う。
- 除外語句はNFC・case foldingによる部分一致で判定し、タイプミス候補で意図しない除外をしない。画面と仕様にこの差を記す。
- 除外の対象範囲は正の条件と同じ。行検索で別行の除外語を見つけても、その行を除外しない。
- 索引の候補絞り込みと、条件の最終評価を分離する。
- 同じ行で「顧客」「必須」が別セルにある場合、セルIDのAND交差を取ると漏れる。語ごとの候補を `groupKey` へ変換してAND/ORを評価する。
- 正の候補行・ファイルを得た後、その範囲の全文字列を取得して除外条件を判定する。ヒットしたセルだけからNOTの成立を決めない。
- 候補絞り込みが難しい短語や条件は走査へ戻す。絞り込みによる検索漏れを許容しない。
- 読み取りが失敗したファイルのファイル範囲AND/NOTを「成立」と判定しない。取得済みの独立した単位のヒットは保持できる。

### 受け入れ条件

1. A12=顧客番号、D12=必須を「顧客」「必須」で検索し、行範囲では1件、同じセル範囲では0件になる。
2. 顧客が12行、必須が13行なら、行範囲では成立せず、ファイル範囲で成立する。
3. 対象範囲内/外の除外語で結果が正しく変わる。
4. 1語句中の空白、AND/ORという文字、記号がそのまま検索できる。
5. 根拠セル・語句・強調位置、結果数が契約と一致する。
6. 索引あり/なし、あいまい検索あり/なしの4組み合わせを確認する。

## 8. P4a・P4b / 機能6: Office抽出範囲の拡張

### 対象と分割

| 段階 | 形式・場所 | 場所情報・重複の扱い |
| --- | --- | --- |
| P4a | Excelの数式文字列 | シート名・セル番地。保存済み結果値と別種別として表示 |
| P4a | PowerPointのノート | スライド番号・ノート内の段落/図形識別。スライド番号等のプレースホルダーを除く |
| P4b | Excelの従来コメントとスレッド形式コメント | シート名・セル番地・コメント識別。スレッドの各本文を区別 |
| P4b | Wordのヘッダー・フッター | 部品・種類・段落/表内位置。複数セクションが共有する同じ部品は一度だけ抽出 |
| P4b | Wordコメント | コメント識別と本文。参照先は取得できる範囲で表示 |

今回のWord拡張はヘッダー・フッター・コメントまで。脚注、文末脚注、変更履歴の削除部分、SmartArt、OCRは含めない。

### 検索条件と抽出規則

- 検索条件に「注記も検索」「数式文字列も検索」を追加する。初期値・API未指定時はともにオフにして、従来の結果と件数を維持する。
- 注記はExcelコメント、PowerPointノート、Wordヘッダー・フッター・コメントをまとめて指定する。初版では形式ごとの細かい設定を要求しない。
- 新しい種別を場所表示・コピー・出力・索引復元まで通して対応する。
- Excelの共有数式では、基点に保存された式は検索し、従属セルで式が保存されていない場合は式を捏造しない。必要な共有式参照を表示し、「各セルでExcelが評価する式を完全再現する」機能とは分ける。
- コメントは本文を正本とし、既存のVML図形抽出と同じコメントを二重計上しない。通常のVMLテキストボックスは従来どおり検索する。
- リレーションシップから部品を辿り、ZIP内のファイル名や部品順を固定前提にしない。
- ノートの日時・フッター・スライド番号など、本文ではないプレースホルダーは型情報に基づいて除外する。
- 実行、再計算、外部参照の取得を行わず、既存のZIP/XML資源上限を維持する。

### 一部の部品が壊れている場合

現在の抽出は `Result<Vec<Unit>, ExtractError>` なので、P4では抽出結果を「取得済みUnitと部品単位Issueを返せる形式」へ拡張する。

- 本文が読めて注記部品だけ壊れている場合、本文のヒットを保持し、一部エラーとして表示する。
- 本文の列挙自体ができない場合は従来と同じファイルの読み取りエラーとする。
- 同一部品の同一障害を複数箇所から参照してもIssueを重複させない。
- 不完全な抽出結果を完全な索引として保存しない。
- ファイル範囲の複数条件は不完全な抽出結果で成立させない。現在のエラー付き結果表示と集計を更新し、この意味を境界契約へ記載する。

### 受け入れ条件

1. 注記/数式をオフにしたとき既存ケースの結果・件数が変わらない。
2. 数式の文字列と保存済み結果が別種別・同じセルの場所として確認できる。
3. 従来/スレッド形式コメントを取得し、VMLと重複しない。
4. ノート本文は取得し、ページ番号等はヒットに含めない。
5. 共有ヘッダーを複数セクションで参照しても重複しない。
6. 壊れた注記、外部リレーション、暗号化、資源上限でも残りの検索を継続できる。
7. 検索範囲の切り替えで索引を正しく無効化し、直接読み取りと同じ結果を返す。

## 9. P5 / 機能7: 検索順位

### 方式

今回の順位付けは既存の一致方式と構造化した根拠を使う。日本語辞書や学習モデル、利用者による重み設定を要求しない。BM25等の導入は、評価結果から必要性が分かった場合の別変更とする。

`score` は既存の意味で保持し、ファイル単位の `RankingEvidence` を追加する。

| 順位に使う情報 | 初期の扱い |
| --- | --- |
| 一致方式の品質 | 通常検索は現行の強い一致を優先。複数条件は各正の語の最良一致のうち最も弱いものも考慮し、弱いAND成立を見分ける |
| 正の検索語の充足数 | ORや複数条件で、より多くの異なる検索語を満たす結果を優先 |
| 同じ行への集中 | 同じ行で複数語が揃う結果を、文書内に散在する結果より優先 |
| 本文にある根拠 | 同程度の一致なら、ファイル名・注記だけより本文で確認できる結果を優先 |
| 異なる根拠の数 | 同じ場所の反復や同一ヘッダーの重複で順位が上がらないよう、場所を重複排除し加点を上限付きにする |
| 同点 | 正規化したファイルパス、構造化した場所順で固定する |

「同じ行への集中」は検索範囲外の注記・数式を含めず、P3の条件判定と同じUnitから計算する。除外語は順位の加点対象にしない。

初期の比較順序は、一致方式の品質 → 正の語の充足数 → 同じ行の充足数 → 本文の根拠 → 上限付き根拠数 → パス/場所。係数を調整する方式ではなく、この順序の比較を基準に評価する。

### コア・GUI・イベント

- `ranking.rs` が順位の根拠と比較キーを計算する。GUI内の重複した順位規則を取り除く。
- コアはファイルを処理し終えた時点で順位要約を通知する。検索全体の終端前に、通知済みヒットの要約を確定する。
- 検索中の画面は現在と同じ到着順とし、完了・中断時に確定した順位で並べる。
- CLI・調査記録にも同じ順位情報を渡し、GUI固有のDOMから計算しない。
- GUIは「3語に一致」「同じ行で2語に一致」等の短い理由を表示する。複合順位を一致確率として表示しない。

### 評価

少なくとも20件の固定クエリと、各クエリの優先すべき文書・場所を用意する。文書名だけ一致、本文一致、同じ行のAND、別行のAND、注記だけ一致、大量の同語反復、かな/識別子の揺れ、タイプミスを含める。

- 必ず上に置くべき結果のペアが逆転しないことを機械検証する。
- Top-5の根拠と順位を旧版と比較し、改善・悪化例を記録する。
- 一致方式の点数そのものを変えて辻褄を合わせない。
- 未描画の結果も順位に含め、中断時には未処理の文書の評価を作らない。

## 10. P6 / 機能4: 複数IDの一括検索

### 入力と意味

「一括検索」モードに改行区切りの入力欄を設ける。1行が1検索語で、空行を除去し、同じ正規化語はまとめる。元の入力順と表記を表示用に保持する。

- 初期の上限案は256語。開始前に件数を示し、上限超過は入力エラーにする。負荷確認で上限を見直す。
- 照合方法は「識別子一致」を初期値とし、「通常の文字列検索」も選べるようにする。
- 識別子一致はNFCとcase foldingを用い、前後の識別子文字の境界を確認する。`TAB_01` が `TAB_010` にヒットしないことを必須とする。
- 日本語の項目名など、識別子として扱えない語は通常の文字列検索を使う。行ごとの対応方法を入力検証結果で説明する。
- 通常の文字列検索は現行の部分一致と `fuzzySearch` を利用できる。識別子一致ではタイプミス・幅/記号差による自動拡張を行わない。

### 実装

- フォルダー列挙は1回、文書抽出も各ファイルにつき1回とし、複数語を同じ抽出結果へ照合する。
- 「検索語数分の `run_search` を順に呼ぶ」実装にしない。P3のクエリ計画・候補選択を利用する。
- 索引ありでは複数語の候補をまとめて取得し、同じ文書・Unitの読み取りを重複させない。
- 各結果に検索語IDを付け、通常のResult件数とは別に語ごとのファイル数・ヒット数を集計する。
- 新しい語別要約通知を終端前に返す。取消し後も `Finished` が一度だけ届く契約を維持する。
- 入力順で語別一覧を表示し、語の詳細を展開するとP5の順位で文書・場所を表示する。

### 一覧と出力

標準一覧は「検索語、該当ファイル数、該当箇所数、確認状態」。詳細は文書名・場所・抜粋を表示する。語×ファイルの表は、画面では必要な範囲を段階表示し、全体はCSV/TSVへ出力できるようにする。

| 実行状態 | ヒット0件の表示 |
| --- | --- |
| 指定範囲を完了し、読み取りエラーなし | 指定範囲内で該当なし |
| 一部の対象を読めなかった | 未確定（一部エラーあり） |
| 中断・全体失敗 | 未確定（中断/失敗） |

文字列の登場箇所を示す機能であり、登場したテーブルを実際に更新する、画面が呼び出す等の依存関係を断定しない。「要確認の登場箇所」として変更影響調査に使う。

### 受け入れ条件

1. 重複・空行・大文字小文字違いを含む入力から、表示と集計が一致した一覧を作る。
2. `TAB_01` と `TAB_010` を区別し、通常の部分一致との違いを確認できる。
3. 語数が増えてもフォルダー列挙・文書抽出回数が増えないことを計測する。
4. 同じ場所で複数語が一致したとき、語別・全体の件数が定義と一致する。
5. 一部エラー・中断時に、0件を「存在しない」と断定しない。
6. 一覧、詳細、出力で同じ検索語と結果を参照する。

## 12. テスト方針と完了条件

### テストデータ

固定シードで、以下の目的を満たす専用文書を追加する。既存の通常検索ケースを残し、新ケースは別の生成フォルダーに置いて既存件数への影響を制御する。

| データ | 確認すること |
| --- | --- |
| 項目名・型・桁数・必須・説明が別セルのExcel | 周辺表、行AND、根拠セル |
| 同じ語が別行/別シートにあるExcel | 判定範囲、NOT、グループ境界 |
| 疎なセル、結合セル、非表示行列、遠い列 | メモリ使用量、座標、表示上限 |
| 保存済み結果と異なる数式文字列 | 数式検索、種別、キャッシュの範囲変更 |
| 従来/スレッド形式コメント、VMLテキストボックス | コメントと図形の識別・重複排除 |
| PPTノートと番号等のプレースホルダー | 本文の取得・不要な重複の除外 |
| Wordの共有ヘッダー、表、コメント | 部品の重複、本文との場所の区別 |
| 壊れた注記部品・外部リレーション | 部分抽出とエラー集計 |
| `TAB_01` / `TAB_010` / 混在表記 | 識別子境界と通常検索の区別 |
| CSV/TSVを壊す文字や数式先頭文字 | 一括コピー・出力 |
| 優先関係が明確な文書群 | 順位評価、同点の安定性 |

### 各変更で策定する確認手順

1. 既存の通常検索・あいまい検索・エラー・中断の回帰確認。
2. 新機能の受け入れケースと、索引あり/なしの同値確認。
3. 注記/数式の対象変更、ファイル更新・削除、索引版変更・破損の確認。
4. 大量結果、周辺表示を繰り返したときのメモリ、複数語数の負荷確認。
5. CLIとGUIの結果・順位・件数、出力との一致確認。

実行手順は現在の `docs/development.md` を基準に、共通バックエンドケース、コアのテスト、WASMチェック、Windowsビルド、必要なGUI確認を各変更に対応付ける。Linuxのコア確認だけでWindowsの保存ダイアログ・クリップボード・実行ファイルの確認が済んだとは扱わない。

性能は初回抽出・索引再利用を分け、文書数/サイズ、語数、経過時間、最大メモリ、処理/抽出回数、取消し応答を記録する。絶対時間の合格値は対象端末で基準測定後に設定する。

### リポジトリの作業ルール

現在の `AGENTS.md` に従う。実装だけを依頼された変更では、実装・静的確認・テスト方針の作成までを行い、テスト実行・ビルド・GUI起動・リモート反映は別の依頼範囲とする。テスト・ビルドまで依頼された場合は、その範囲を実施する。GUIテストは依頼に明示されている場合を除き、実施前の確認が必要。

変更の完了報告には、変更した挙動、仕様、静的確認、実施済み/未実施の確認、次の担当モデルがそのまま使える確認項目・手順・期待結果を記す。

## 13. 次の実装担当への引き継ぎ

最初にP1だけを実装し、出力のデータモデルをP3/P6で拡張できる形にする。P1の後にP0を実装する。全機能を一度の大きな変更で入れず、各段階で旧モードの互換性を確認できる状態を保つ。

着手時に行うこと:

1. 最新mainと `AGENTS.md` を確認し、本計画の基準コミットとの差分を読む。
2. 該当段階の要求・境界契約と、既存ケースの維持条件を先に整理する。
3. 実装・仕様更新・テスト方針を同じ変更に含める。
4. 指定された範囲の確認を行い、未実施の作業を区別して報告する。

この計画で定めた初期値は実装時の推奨値。互換性や性能の根拠によって調整した場合、仕様・期待値・報告を同時に更新する。
