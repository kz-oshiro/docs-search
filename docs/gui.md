# docs-search 再構築版: GUI 仕様

この文書は利用者に見える操作と表示を定義する。レイアウトの寸法、色、GUI フレームワークは指定しない。[全体仕様](./requirements.md)と[境界契約](./boundary.md)を併せて参照する。

## 入力と操作

| 要素 | 要求 |
| --- | --- |
| 検索フォルダー | 最初の1件は必須とし、「追加」で複数のフォルダーを指定できる。各欄でパスの入力・貼り付けとフォルダー選択ができ、追加した欄は削除できる。存在するフォルダーを必須とする。 |
| 対象外フォルダー | 「追加」で任意の件数を指定できる。各欄でパスの入力・貼り付けとフォルダー選択ができ、欄を削除できる。指定したフォルダーの配下は検索対象に含めない。 |
| 検索語 | 1 件の文字列を入力する。前後の空白を除いた後に空なら検索を開始しない。複数語演算や正規表現の UI は設けない。 |
| 検索する拡張子 | 対応する93拡張子を用途別の分類から複数選択できる。全体と分類ごとに一括選択・解除でき、選択数が分かる。初期状態では対応する93拡張子をすべて選択する。1種類も選ばれていなければ検索を開始せず、理由を示す。 |
| 検索 | 有効な入力で 1 回の検索を開始する。同じ画面で並行して複数検索は行わない。 |
| 結果の絞り込み | 検索済みの結果をファイル名・パスに含まれる文字列と拡張子で絞り込める。絞り込みの解除もできる。 |
| 中断 | 検索中に使用できる。要求後は「中断中」と表示し、終端通知を受けるまで待つ。 |
| ファイルを開く | 各ファイルのファイル名リンクから元ファイルを既定アプリで開く。文書内の位置への自動ジャンプは保証しない。ファイルが移動・削除されていた場合は説明する。 |
| 場所をコピー | 各一致箇所のコピーアイコンから、その結果の絶対パスと場所を人が読める形でコピーする。 |

初期画面のフォルダー初期値は利用環境に合わせて選べるが、検索は利用者の操作で開始する。バックエンドはフォルダー選択、元ファイル起動、クリップボード操作を担当しない。
検索フォルダーが重なる場合は同じファイルを重複表示しない。対象外フォルダーは検索フォルダーの指定より優先する。存在しないフォルダーや空欄があれば、対応する欄の近くに理由を示して検索を開始しない。

## 結果一覧

検索結果はファイルごとに1つのまとまりで表示し、同じファイルの一致箇所をその下に並べる。ファイルの見出しには一致件数とファイル名のリンクを示し、クリックで元ファイルを開けるようにする。拡張子はファイル名の左に色付きのタグで示し、ファイルパスはファイル名の下に小さめの灰色の文字で表示する。各一致箇所には文書内の場所、該当文字列を含む抜粋、場所をコピーするアイコンを置く。抜粋内の一致箇所は背景色などで強調し、文字を読める状態に保つ。抜粋は一致箇所が分かる文脈を含め、長い内容を省略する場合は省略したことが分かる表示にする。ファイル名一致も結果として表示する。場所の表記例は以下のとおり。

| 形式 | 場所の例 |
| --- | --- |
| Excel | `Sheet1!C12`、`Sheet1 / 図形名` |
| PowerPoint | `スライド 3 / 図形名` |
| Word | `本文 段落 12`、`表 2 / 行 3 / 列 1` |
| テキスト・ソースファイル | `行 42` |
| ファイル名 | `ファイル名` |

GUI は検索中にファイルと一致箇所を到着順で追加し、完了・中断時に最高スコア順へ並べ替える。同点はファイルパスと場所で安定して並べる。各一致箇所には一致理由の短いラベルを表示し、数値スコアは表示しない。結果件数はファイル数ではなく一致箇所の件数とする。並べ替えや絞り込みでも元の結果と件数を失わない。結果が 0 件なら「該当なし」を表示し、読み取りエラーがある場合はその件数も併記する。検索用索引は端末内へ自動保存し、利用者が画面から削除できる。

結果の絞り込みは表示中の結果だけに適用し、検索処理を再実行しない。文字列は大文字・小文字を区別せずファイル名またはパスに含まれるかで判定し、拡張子は結果に現れた種類から選ぶ。両方を指定した場合は両条件を満たすファイルを表示し、そのファイルの一致箇所はすべて保持する。絞り込み中も全体の結果件数を変えず、表示対象のファイル数・一致件数と全体数を別に示す。検索中に届いた結果にも現在の条件を適用する。新しい検索を始めると条件を解除する。

## 進捗とエラー

- 列挙中、検索中、完了、中断、全体失敗を区別する。検索中は処理済みファイル数を表示し、総数が確定しているときだけ分母や割合を表示する。
- 画面上で結果件数とエラー件数を確認できる。1 ファイルの失敗は、対象パスと簡潔な理由を一覧に残す。パスが取得できない列挙エラーも別件として表示する。
- 読み取りエラーがある場合は進捗表示の直下に件数付きの折りたたみ欄を示し、展開して個別の内容を確認できるようにする。ファイルを開く操作やコピー操作の失敗は画面上の通知で示す。
- 一致箇所のあるファイルで読み取りエラーも起きた場合は、そのファイルの結果をエラー用の色と文字ラベルで示す。エラーの理由は折りたたみ欄でも確認できるようにする。
- 一部のファイルが読めなくても、終端状態は「完了（一部エラーあり）」とし、結果を保持する。全体失敗と同じ表示にしない。
- 入力エラーは該当欄の近くに示す。検索開始後の全体失敗は、原因と途中までの結果が残ることを示す。
- 長い検索で結果が増えても画面操作と中断操作ができること。進捗通知の表示頻度は GUI 側で調整してよいが、最終件数は終端通知と一致させる。

## 状態と遷移

| 状態 | 検索 | 中断 | 表示 |
| --- | --- | --- | --- |
| 待機 | 有効 | 無効 | 入力可能。前回の結果は保持してよいが、新規検索を受理した時点で消す。 |
| 列挙・検索中 | 無効 | 有効 | 新しい結果・進捗・エラーを順次追加する。 |
| 中断中 | 無効 | 無効 | 処理停止を待っていることを示す。 |
| 終了 | 有効 | 無効 | 完了・中断・失敗の別と最終件数を示す。結果を保持する。 |

新しい検索を始めたら、その検索 ID に属する通知だけを表示する。前の検索の遅延通知で結果を汚さない。画面を閉じる際に実行中の検索があれば中断を要求し、処理を残したままにしない。

## 操作性

- 入力欄と主要ボタンには見分けられるラベルを付け、キーボードでも検索、中断、各結果のファイルを開く操作と場所のコピーができること。コピーアイコンには操作対象が分かる名前を付ける。
- 処理中・終了時の状態は色だけに頼らず文字でも示す。エラーと入力検証の文言は、次に取れる行動が分かる表現にする。
- パスと場所情報は全文を確認・コピーできる手段を用意する。抜粋を省略する場合も一致語を残し、省略を明示する。
