# docs-search v3.0.2

現行文書を改訂するたびに製品版番号を更新する必要がないよう、仕様・開発手順・試験設計の版表記と参照を整理しました。

## 変更

- 現行文書のタイトル・説明から製品版番号を外し、Rust要求仕様のファイル名を `rust-requirements.md` に揃えました。改訂履歴はGitで管理します。
- 公開・検証記録の索引を追加し、配布案内は最新のGitHub Releaseへリンクしました。リリースノート・検証記録と依存ツールの版情報は残します。
- 現在の実装状況と過去の実装・検証履歴を分けました。過去の検証記録からは当時の要求仕様を参照できます。
- 試験設計をバックエンド試験・フロントエンド試験・アプリケーション結合試験の3区分に統一しました。個別試験で観測できない接続のみ結合試験に回します。

今回の製品版更新はリリース依頼に伴うものです。今後、文書改訂だけで製品版を上げる必要はありません。検索処理・画面処理・既存の試験コードと外部依存の版は変更していません。

## 検証

- バックエンド試験: Rustコア/公開API 64件と実CLI全6群が成功しました。17性質を各1,024ケース、固定seed `3000002` で確認しました。
- フロントエンド試験: ヘッドレスPlaywright 54件が成功しました。skipped/unexpected/flakyは0、画像・動画・トレースなしです。
- 共通の検証基盤: 生成器3件が成功し、画面・配布用stagingの8資材のSHA256がソースと一致しました。
- Windows Releaseビルドが成功しました。検証後は公開記録だけを追加し、同じEXEを配布します。

アプリケーション結合試験9ケース群とフロントエンドのG01/G02拡張は設計段階で、今回の成功件数に含めていません。OS固有の操作・表示の保証範囲は[アプリケーション結合試験設計](https://github.com/kz-oshiro/docs-search/blob/v3.0.2/docs/test-plans/playwright-exe-test-plan.md)に記載しています。詳細は[検証記録](https://github.com/kz-oshiro/docs-search/blob/v3.0.2/docs/releases/validation-v3.0.2.md)を参照してください。
