検索の流れ

要求を受けてから画面に結果が届くまで。

画面が要求を作る

検索フォルダー、語句、拡張子、検索設定から SearchRequest を作成します。

Tauriが検証して開始

start_search が要求を検証し、同時検索を防いで検索セッションとキャンセル状態を用意します。

コアが文書を調べる

対象フォルダーを走査し、選択形式を抽出して、通常・高度・一括の検索条件を評価します。

イベントを順に発行

Started、Progress、Result、Issue、Finished などで状態を通知します。

Tauriがまとめて転送

結果を最大128件単位でまとめ、その他の境界イベントとともに search-events を送ります。

JavaScriptが表示を更新

イベントが現在の検索IDに属するかを確認し、件数・進捗・ファイルごとの結果・Issueを画面に反映します。

境界の要求

SearchRequest は検索場所と条件を表します。Tauri側はコア実行前にも検証し、実行中は検索IDに紐づけてキャンセル要求を管理します。

境界のイベント

SearchEvent は searchId、コアが発行ごとに増やす sequence、イベント種別を持ちます。個別ファイルの問題はIssueイベントとして結果と分けて扱います。

ビルドと確認の境界

ソースコードからデスクトップ版と自動確認ができるまで。

デスクトップ版のビルド

  1. cargo xtask build が frontend の8資材を内容に変更があった場合だけ staging。
  2. HTML・CSS・テーマ関連ファイルを target/frontend-dist/ に配置。
  3. Cargo/TauriがJavaScript画面とRustコアをWindows実行ファイルにまとめる。
  4. debug/release cache を保持し、成功 EXE と SHA256 を実行別 outputs/runs/ に保存。

自動確認の構成

  1. 共通データ・CLI受け入れランナーがコアの入出力を確認。
  2. CargoのRustテストと生成器/実CLI検証がエンジンと画面のコードを確認。
  3. Playwrightが実際のHTML/CSS/JavaScript画面をヘッドレス操作。Tauri IPC境界はテスト用モックを使う。
  4. 実アプリGUI、Windows OS連携、配布ビルドは自動テスト入口と別の範囲。
