# docs-search 再構築版: バックエンド仕様

検索バックエンドはフォルダーの列挙、文書からの文字列抽出、照合、結果と進捗の通知を担当する。GUI や OS の画面部品には依存しない。入出力の意味は [境界契約](./boundary.md) に定義する。

## 列挙と検索規則

1. 指定された検索フォルダーを再帰的に列挙し、下表から選択された拡張子のファイルだけを対象とする。対象外フォルダーとその配下は列挙しない。対象外指定は検索フォルダーの指定より優先し、検索フォルダー同士が重なっても同じパスのファイルを二重計上しない。拡張子は大文字・小文字を区別しない。未選択の形式と対象外フォルダー内のファイルは発見・処理・結果・エラーの件数に含めない。隠し属性や先頭のドットだけでは除外しない。`~$` で始まる Office 一時ファイルとシンボリックリンクは除外する。
2. 検索語は前後の空白を取り除き、空なら入力エラーとする。正規表現や複数語演算ではない、1 語句の検索とする。
3. 原文を表示用に保持し、NFC と Unicode case folding による基本形、NFKC と case folding による幅吸収形、かな種別と識別子区切りを吸収した検索形を別に作る。アクセント除去、語幹変化、同義語展開は行わない。大文字境界は case folding より先に検出する。数字だけの検索語では区切り記号を除去しない。
4. ファイル名は拡張子を含めて照合する。内容の一致は下表の「検索単位」ごとに判定し、同じ単位に検索語が複数回出ても結果は 1 件とする。別の単位、ファイル名と内容の一致は別件とする。
5. 検索対象の値は保存済みデータに限る。文書を編集・再計算・実行しない。外部参照の取得もしない。

検索中にファイルが変化した場合は、そのファイルの読み取り時点で得られた内容を扱う。一貫したスナップショットは保証しない。途中で読めなくなったファイルは個別エラーにする。

| 分類 | 対応拡張子 |
| --- | --- |
| Office 文書 | `.xlsx` `.xlsm` `.pptx` `.docx` |
| テキスト・文書・表データ | `.txt` `.md` `.markdown` `.mdx` `.rst` `.adoc` `.log` `.csv` `.tsv` |
| Web・マークアップ | `.jsp` `.xhtml` `.html` `.htm` `.vue` `.svelte` `.astro` `.css` `.scss` `.sass` `.less` `.svg` |
| JavaScript・TypeScript | `.js` `.mjs` `.cjs` `.jsx` `.ts` `.mts` `.cts` `.tsx` |
| プログラム・スクリプト | `.java` `.kt` `.kts` `.groovy` `.gradle` `.py` `.rb` `.php` `.go` `.rs` `.c` `.h` `.cc` `.cpp` `.hpp` `.cs` `.swift` `.scala` `.sh` `.bash` `.zsh` `.ps1` `.bat` `.cmd` `.sql` `.dart` `.lua` `.r` `.jl` `.pl` `.ex` `.exs` `.clj` `.cljs` `.fs` `.fsx` `.vb` `.vbs` |

## 形式ごとの抽出範囲

| 形式 | 検索単位と内容 | 場所情報 | 初期版の対象外 |
| --- | --- | --- | --- |
| `.xlsx` / `.xlsm` | セルの保存値、保存済み数式結果、標準図形・テキストボックスの文字。文字列が複数の書式ランに分かれていても結合して照合する。 | シート名とセル番地、またはシート名と図形名・位置 | 数式そのもの、未保存の計算結果、表示書式後の値、グラフ、SmartArt、コメント、マクロ |
| `.pptx` | 各スライドの通常のテキスト図形と表セルの文字。図形内で書式ランに分かれた文字は論理的な文字列として照合する。 | スライド番号と図形名または表の行・列 | ノート、マスター、埋め込み文書、グラフ、SmartArt、画像中の文字 |
| `.docx` | 本文の段落と表セル内の段落。書式ランをまたぐ語句も照合する。 | 本文の段落番号、または表の階層・行・列・セル内段落番号 | ヘッダー、フッター、脚注、コメント、変更履歴の削除部分、埋め込み文書、画像中の文字 |
| 上表の Office 以外の拡張子 | UTF-8、UTF-8 BOM、Shift_JIS（Windows-31J 相当）で読んだ各行の文字。コード・マークアップ・CSV・JSON・ノートブックなどの構文を解析せず、保存された文字列をそのまま照合する。 | 1 始まりの行番号 | 他の文字コード、バイナリ、改行をまたぐ一致、実行・レンダリング後の文字 |

Excel の数値はファイルに保存された値の文字列表現で照合し、日付などの表示書式を適用しない。論理値は `TRUE` / `FALSE` として扱う。数式は保存済みの結果があるときだけ結果値を検索する。図形名がない場合も、シートまたはスライドと、取得できる位置や通し番号で結果を区別できるようにする。

非表示シート・非表示スライドも対象とする。Word の表内段落は本文の段落として重複計上しない。入れ子の表は外側からの表・行・列の経路で場所を示す。PowerPoint の表セルも図形全体の文字として重複計上しない。テキスト形式はファイルごとに UTF-8 BOM を優先し、BOM がなければ UTF-8、読めない場合は Shift_JIS として解読する。デコードできないデータは置換文字にして検索を続けず、そのファイルの読み取りエラーとして報告する。

## 処理単位と失敗

- ファイル単位で抽出処理を分離する。1 ファイルの破損、暗号化、権限不足、形式不正はそのファイルのエラーとし、残りのファイルを継続する。
- 列挙中のアクセス拒否などは、取得できたパスと理由を列挙エラーとして報告し、探索できる別の場所を続ける。
- 全体失敗は、検索を開始・継続できないバックエンド自身の障害に限る。個別エラーがあっても処理を終えたなら「完了（一部エラーあり）」に相当する集計を返す。
- 不正な入力は検索開始前に検出する。検索途中の中断では、既に通知済みの結果・エラーを取り消さない。
- 追加の検索フォルダーと対象外フォルダーも、存在するディレクトリか検索開始前に検証する。重複・親子関係は正規化したパスで判定する。
- 検索のたびにフォルダーの現状を調べる。検索単位の原文と正規化形をアプリのユーザーデータ領域のローカル索引に自動保存し、更新日時とサイズが変わったファイルだけ再抽出する。索引を使えない場合は文書を読み直して検索を続ける。元文書への書き込みや外部送信はしない。

## あいまい検索と順位

原文の語・識別子一致 100、NFC と case folding 98、NFKC の幅差 95、空白・区切り記号差 92、identifier 分割一致 90、かな種別差 88、トークン前方一致 80、部分一致 70、編集距離一致 50 とする。検索単位内で最も強い方式を採用し、同じ単位は1件だけ通知する。N-gram は索引から候補を絞る用途だけに使い、共有 N-gram だけでは結果にしない。

編集距離は英字だけの単一トークンで6～10文字は距離1、11文字以上は距離2までとし、先頭文字一致と距離÷検索語長 0.2 以下を条件にする。5文字以下、数字や英数字混在コード、日本語には適用しない。短い検索語は索引内の検索単位を走査するが、文書を毎回再抽出しない。索引の破損・形式変更時は再構築する。索引の削除操作は GUI から実行できる。

## 安全性と拡張性

- 文書は読み取り専用で開き、マクロ・スクリプト・埋め込みオブジェクトを実行しない。外部 URL、外部ファイル参照、外部実体を解決しない。
- 圧縮文書の展開量や XML 等の解析に対して、過大な資源消費を防ぐ制限を設ける。制限に当たったファイルは理由を示す個別エラーにする。
- 形式ごとの抽出器は、共通の「検索単位の文字列と場所」を返す責務に限定する。列挙、照合、進捗集計、キャンセルは共通部分で扱う。新形式の追加で GUI と既存形式の検索規則を変更せずに済むこと。
- 性能のために並列化やバッチ処理を採用してよい。ただし結果件数、各結果の場所、終端通知の意味は変えない。結果の到着順には依存しない。

概念上の流れは「対象ファイルの列挙 → 形式別の検索単位抽出 → 共通の照合 → 結果・エラー・進捗の通知」である。これは処理責務の分割であり、クラス構成やプロセス構成を指定しない。

## 共通検証データ

[tests の共通ジェネレータ](../tests/README.md) が既存10拡張子と追加形式の代表例を含む検索用文書を同じシードで生成する。`backend-cases.json` は各バックエンド操作への入力、該当箇所、Issue、終了集計の期待値を持つ。実装言語や採用ライブラリが変わっても、ジェネレータと検証ケースを共有する。各実装では境界契約との変換を担当する薄いテストアダプターを用意し、共通ケースを直接書き換えない。仕様の変更が必要なときは、この文書と共通ケースを同じ変更として更新する。
